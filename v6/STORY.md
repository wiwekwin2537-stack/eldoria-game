# เนื้อเรื่อง v6 — แสงที่พากลับบ้าน

## สถานะและขอบเขต
เจ้าของสั่ง 2 พฤศจิกายน 2026 ให้พัฒนาเฉพาะเอโดเรีย เปลี่ยนเนื้อเรื่องใหม่และเขียนใบงาน รายละเอียดต่อไปนี้เป็นฉบับออกแบบของผู้พัฒนาตามคำสั่งนั้น ไม่ใช่การอ้างว่าเจ้าของอนุมัติรางวัล/ตัวเลขใหม่ทุกตัว
เรื่องในไฟล์นี้และ `src/data/story.js` เป็นฉบับ v6; `../STORY.md` เก็บเกมเดิมไว้เทียบ ไม่แก้เกมเดิม
บท 0–26 และส่งท้าย ใช้ chapter id คงที่ตามตาราง ไม่ใช้เลขแถวแทน id เนื้อเรื่องจบในเอโดเรีย ไม่มีคำชวนไปเมืองอื่น
สถานะรอบนี้: **ออกแบบแล้ว + ข้อมูลบทและแกนความก้าวหน้าเขียนแล้ว; มีบริการเควสต์ E3a พร้อมกระเป๋าและรางวัลจริงชุดแรก0–2 E3b1ที่ทดสอบแล้ว แต่ยังไม่เชื่อม NPC/หน้าจอ/ต่อสู้จริง จึงยังเล่นเนื้อเรื่องนี้ในเกมไม่ได้**

## เรื่องย่อ
ผลึกอรุณใต้ปราสาทเคยกั้นเงาที่คุกคามเอโดเรีย คืนหนึ่งผลึกแตกเป็นห้าส่วน ผู้เล่นตื่นในวิหารแห่งแสงโดยจำอดีตไม่ได้ มีเพียงเสียงระฆังและตราบนข้อมือที่นำกลับไปหาพระราชาอัลดริค

ระหว่างช่วยคนงาน ช่าง และกิลด์ ผู้เล่นพบว่าตนเคยเป็นผู้ช่วยของผู้รักษาผลึกคนก่อน อัลดริคเคยสั่งปิดผนึกเพื่อช่วยเมือง ขังผู้รักษาไว้ข้างล่าง ผู้เล่นรอดออกมาพร้อมแสงสุดท้ายและสูญเสียความทรงจำ ผู้รักษาคนนั้นค่อย ๆ กลายเป็นจักรพรรดิเงา

การประกอบผลึกคืนช่วยเมืองได้แต่ยังช่วยคนในผนึกไม่ได้ ผู้เล่นจึงค้นวิธีกระจายแรงผนึกสู่แท่นทั้งหก ใช้หอคอย ดันเจี้ยน และหอผนึกเดิมเป็นทางค้นคำตอบ การต่อสู้ครั้งสุดท้ายแยกเกราะเงาออกจากผู้รักษา เมืองยอมรับอดีตและเลิกฝากความอยู่รอดไว้กับการเสียสละของคนเดียว

## โครงอารมณ์
- บท 0–5: จากคนแปลกหน้าสู่คนที่เริ่มมีหน้าที่ เห็นชีวิตชาวเมืองก่อนปริศนาใหญ่
- บท 6–13: เศษผลึกและความจริงของอัลดริค คืนแสงให้เมือง เป็นตอนจบช่วงแรกและปลดล็อกบ้านตามกติกาเดิม
- บท 14–20: ถามว่าชัยชนะช่วยใคร หาวิธีคลายผนึกผ่านพื้นที่เดิม
- บท 21–26: ชาวเมืองร่วมเตรียมพร้อม ลงสู่ชั้นลึก พาผู้รักษากลับบ้าน
- ส่งท้าย: กลับใช้ชีวิตในเอโดเรีย ทำเนื้อหาหลังเรื่องต่อได้ ไม่เปิดภาคเมืองอื่น

## ตัวละครและสถานที่
ใช้เทพธิดา พระราชาอัลดริค ช่างเหล็ก ปรมาจารย์ กิลด์ ชาวเมือง และผู้รักษาที่เปิดเผยว่าเป็นจักรพรรดิเงา ไม่ต้องสร้าง NPC ใหม่เพื่อเดินเรื่องเพิ่ม เทพธิดาให้ความหวังแต่ไม่บังคับชะตา อัลดริคยอมรับความผิดด้วยคำพูดและการกระทำ
ไม่ย้ายร้าน ประตู หรือ NPC ตามเนื้อเรื่องใหม่ เมื่อทำบทสนทนาให้ใช้พิกัดที่ตรวจจากเกม/แมพจริง ไม่เดาตำแหน่ง

## กติกาเควสต์และการเล่นคนเดียว
- หลักฐานต้องมี event id และ chapterId ของบทขณะเกิดเหตุการณ์ ห้าม adapter เปลี่ยน chapterId ของ event เก่าเมื่อ retry; แกนเก็บ id ที่นับแล้วข้ามบทและในเซฟด้วย
- บทล่าสไลม์/กวาดล้าง/งานกิลด์นับเฉพาะหลักฐานหลังรับบท ไม่เอาจำนวนสะสมเก่ามาหักเอง
- เงื่อนไขความก้าวหน้าถาวร (อาชีพ เลเวล อาวุธ ชั้นดัน หอคอย บอสตำนานต่างชนิด) ให้ adapter ตรวจจากข้อมูลที่ยืนยันแล้วเมื่อรับบทด้วย ไม่บังคับทำซ้ำหากผ่านแล้ว
- บท 2 ใช้ Lv≥5 และอาวุธ tier≥1; บท 20 ตรวจอาวุธที่ถือ +10 ตามกติกาเดิม อย่าใช้ข้อความอาวุธคราฟคนละระดับกับเงื่อนไข
- บท 15 เข้าตลาดเพื่อเห็นชีวิตชาวเมือง ไม่บังคับซื้อขายกับคนจริง; บท 16 ใช้บอสเหมืองเหล็กที่เข้าถึงได้คนเดียว; บท 21/24 ใช้งานกิลด์ที่ทำคนเดียวได้ บอสโลก/อสูรปาร์ตี้ยังเป็นเนื้อหาเสริมตามเดิม
- ไม่เพิ่มภาระสร้างแมพ มอน บอส หรือระบบใหม่เพื่อเล่าเรื่อง ไม่ย้ายดัน/วัตถุดิบ/ชุดนครวารีกลับมา
- ยังคงเพดานเลเวลและกติกาเศรษฐกิจที่อนุมัติ ตัวเลขวัตถุประสงค์เดิมที่คงไว้ไม่ใช่รางวัลใหม่

## รางวัลและเซฟ
`rewardKey` เป็นกุญแจอ้างอิงตารางเศรษฐกิจ ไม่ใช่สิทธิ์ให้ client เพิ่มเงิน/XP/ของเอง บทส่งท้ายไม่มีรางวัลซ้ำ
ก่อนเชื่อมเล่นต้องให้เซิร์ฟเวอร์ตรวจหลักฐานและบันทึก transaction รางวัล + ความก้าวหน้าแบบรับครั้งเดียว กระเป๋าเต็มต้องมีผลลัพธ์ชัดเจน ห้ามเลื่อนบทแล้วทำรางวัลหาย
แกนใน `core/story.js` แยกการขอส่งบทออกจากผลยืนยัน API `confirmReport` เรียกได้จาก adapter ที่รับคำตอบเซิร์ฟเวอร์แล้วเท่านั้น E3aเพิ่ม `server/story.cjs` ที่ใช้แกนเดียวกันและออกผลยืนยันหลังบันทึกแล้ว แต่ยังไม่มี route/client adapter ที่ใช้เล่นจริง
เซฟ story เป็น version 1; import `fm_story` เดิมต้องให้เซิร์ฟเวอร์ตรวจรางวัลและความคืบหน้าก่อน ป้องกันการย้ายบทแล้วรับซ้ำ ห้ามเดาสิทธิ์รางวัลจากเลขบทอย่างเดียว
บทเดิม 27–34 หรือส่งท้ายเดิมย้ายไป `free` เพื่อกระทบยอด บท 0–26 mapping คงที่ แต่การเปลี่ยนเงื่อนไขในบท 15/16/21/24 ต้องกระทบยอดด้วย; ไม่ลดเลเวล ไม่ลบเงินหรืออุปกรณ์
หากข้อมูลรุ่นใหม่กว่า/ผิดรูป ให้หยุดโหลด story และหยุดการเซฟทับจนแก้ได้ ตามงาน SAVE-SAFE ในใบงาน ห้ามแปลงเป็นตัวละครใหม่เงียบ ๆ

## ฉากสำคัญ
### เปิดเรื่อง
เสียงระฆังดังทั้งที่เชือกหอระฆังขาด เทพธิดาบอกเพียงว่า “เจ้ากลับมาถึงแล้ว” ผู้เล่นถามว่าที่นี่คือที่ไหน ก่อนเห็นชาวเมืองกวาดเศษหินจากทางเดิน เริ่มควบคุมตัวละครได้ทันที ไม่ใช้ฉากยาวเพื่อเล่าประวัติทั้งหมด
### จบบท 13
แสงกลับเหนือเมือง ชาวเมืองวางกุญแจบ้านไว้ในมือผู้เล่น อัลดริคกำลังกล่าวขอบคุณ แต่เสียงระฆังดังอีกครั้งจากใต้ปราสาท ผู้เล่นรู้ว่ายังมีคนรออยู่ เรื่องช่วงแรกจบอย่างมีผลต่อเมืองและเปิดเรื่องต่อโดยไม่ต้องเปิดพื้นที่ใหม่
### จบบท 26
หลังปราบเกราะเงา แท่นรับแรงผนึกแทนผู้รักษา อัลดริครับเขาที่ประตูเมืองและขอโทษโดยไม่ขอให้ยกโทษทันที ผู้เล่นเดินกลับบ้าน เห็นไฟที่ชาวเมืองเปิดรอ แล้วได้เลือกชีวิตของตนเอง

## เกณฑ์รับงานเรื่อง
เรื่อง/ชื่อ/เงื่อนไขตรงข้อมูลบท ไม่มีเมืองที่ตัด ไม่มีทางตันจากจำนวนผู้เล่น ไม่มีรางวัลซ้ำเมื่อกดหรือโหลดซ้ำ ต้องทดสอบรับบท → ทำเป้าหมาย → ส่งบท → เซฟ → โหลดใหม่ในเบราว์เซอร์เมื่อเชื่อมระบบแล้ว

## ทางเชื่อมเซิร์ฟเวอร์ E3a (2026-11-02)
`server/story.cjs` สร้างบริการด้วย createStoryService และอ่านข้อมูลบทจาก data/story.js โดยตรง `read` คืนความก้าวหน้าจริงในส่วน server; `record` รับ ticketที่ verifierผูกกับบัญชี/บท; `report` รับchapterId/requestIdและหลักฐานคุยNPCที่ verifierตรวจแล้ว
ระบบไม่เชื่อ systems.story ของclient และไม่เอาจำนวนเงิน/XP/ของจากคำขอclientมาแจก ค่าrewardKeyมาจากบทเอง
บริการยังไม่ถูกสร้างในserver/index และไม่มี WebSocket route ค่าเริ่มต้น rewards/grant/verifierไม่เปิด ต้องทำadapterหลักฐานและกระเป๋าจริงก่อน รูปแบบรางวัลในเทสเป็นfixtureไม่ใช่ตารางที่เปิดใช้
transactionนี้รองรับเฉพาะผู้เขียนคนเดียวผ่านcreateSaves instanceเดียว ต้องทำCAS/การเป็นเจ้าของwriterที่storageก่อนใช้หลายโปรเซส ไม่ยืนยันว่าแก้ความเสี่ยงหลายโปรเซสเดิมแล้ว
รางวัล/receipt/บทถูกเขียนพร้อมกันเป็นserver profileเดียว callbackgrantต้องsyncและไม่มีside effectภายนอก ถ้ากระเป๋าเต็มหรือgrantล้มเหลวให้throw/คืนfalse ไม่มีการเลื่อนบทหรือบันทึกรางวัลบางส่วน
การย้ายเซฟเก่าและneedsReconciliationยังเป็นงานE3b ห้ามล้างธงเพื่อข้ามการตรวจประวัติรางวัล
