## STORY-E3a — รับหลักฐานและธุรกรรมเควสต์ภายในเซิร์ฟเวอร์ (2026-11-02)
เจ้าของสั่งต่อ จึงเพิ่ม `server/story.cjs` ใช้ข้อมูลบท/แกนเดิมผ่าน import ไม่สร้างเรื่องอีกชุด และใช้ `server/saves.cjs` เก็บใน `server.storyLedger` แยกจาก systems ของ client
**สถานะ: โค้ดและตรวจอิสระบริการภายในแล้ว ยังไม่ได้เชื่อมเล่น** ไม่มี WebSocket route ใหม่ ไม่เปิดใน index.cjs ไม่มี verifier จากระบบต่อสู้/NPC จริง ยังไม่แจกเงินจริงในเกม

### สิ่งที่ทำแล้ว
- read/record/report ภายในรับเฉพาะหลักฐาน canonical ที่ verifier ฝั่งเซิร์ฟเวอร์รับรอง ผูกบัญชีและบท; client ส่ง event หรือความคืบหน้าใน systems.story มาแทน ledger ไม่ได้
- report ต้องมีหลักฐานครบและยืนยันการคุย NPC ที่ถูกต้อง; rewardKey มาจากข้อมูลบทบนเซิร์ฟเวอร์ ไม่มาจากคำขอผู้เล่น
- grant/ความก้าวหน้า/receipt อยู่ในสำเนา profile เดียวกันและเขียนเอกสารเดียวผ่านคิวบัญชี; grant ปฏิเสธ/กระเป๋าเต็ม/ที่เก็บพังไม่ทำให้ได้เงินบางส่วนหรือเลื่อนบทค้าง
- idempotency เป็นรายบทและ requestId คงที่ ส่งซ้ำ20คำขอพร้อมกันได้ครั้งเดียว; retryหลังrestartได้receiptเดิม; reuse idข้ามบทถูกปฏิเสธ
- เพิ่ม readServer ที่ไม่เปลี่ยน sid; คืน deep copy จาก load/read/update ไม่เปิด nested cache ให้ callback/ผู้เรียกแก้; callback updateServer ต้อง sync ไม่รับ Promise
- เขียนสำเร็จแต่คำตอบหายต้องล้างแคชแล้วอ่าน storage ใหม่ ไม่ใช้ cache เก่าไปทับreceipt/รางวัล; เซฟ JSONเสีย/รุ่นไม่รองรับไม่ถูกแปลงเป็นตัวละครใหม่

### ขอบเขตที่ยังขาดก่อนเปิดจริง (ห้ามตีความว่า E2/E3/E4 เสร็จหมด)
- รองรับ transaction เฉพาะ createSaves instance เดียวที่เป็นผู้เขียนคนเดียว การสร้าง service ต้องระบุ storageMode:'single-writer'; ยังไม่มี CAS/leaseข้ามโปรเซส ห้ามเปิดกับหลาย server instance
- rewards/grant/verifier ค่าเริ่มต้นไม่เปิด; ตารางรางวัลและกระเป๋าใน `tests/server.story.test.js` เป็น fixture ทดสอบเท่านั้น **ไม่ใช่ค่ารางวัล production ที่เจ้าของอนุมัติ**
