# ผลตรวจ SAVE-SAFE — ผู้ตรวจอิสระ
วันที่ 2026-11-02 · agent ตรวจแยกจากผู้เขียน ไม่ได้แก้ไฟล์หรือเขียนบริการภายนอก ผู้เขียนบันทึกรายงานจากผลตรวจกลับมา

## ขอบเขต
core/save.js, systems/login.js และ tests/save* ตรวจทั้ง snapshot/load/flush/คำตอบ async ที่มาช้า ไม่รวม UI เบราว์เซอร์หรือเซิร์ฟเวอร์จริง

## รอบแรก — ผ่านแบบมีข้อแก้
P2: เซฟเริ่มก่อน serializer พัง เมื่อ flush พบข้อมูลไม่ครบแล้ว ACK ของเซฟเก่ายังเคลียร์ S.failure และแสดง ok:true ทำให้ผู้เล่นเข้าใจว่าปัญหาหายแล้ว ขณะ serializer ยังพัง
ผู้เขียนเพิ่ม regression ที่พังกับโค้ดก่อนแก้ แล้วเพิ่ม failureVersion เพื่อไม่ให้ ACK ล้างข้อผิดพลาดที่เกิดทีหลัง
เพิ่มการจดระบบที่ต้องมีตั้งแต่ snapshot แรกที่ส่ง ไม่รอ ACK ป้องกัน serializer ระบบใหม่คืน undefined ก่อน flush แล้วทำข้อมูลหาย

## ตรวจซ้ำ — ผ่านสำหรับแกน SAVE-SAFE
ผู้ตรวจรัน safety14/14 และ saveเดิม17/17ผ่าน พิสูจน์ว่า serializer พังระหว่างรอ ACK แล้ว flushไม่ส่ง ACKเก่าไม่ล้างป้าย; ระบบใหม่ที่เคยส่งข้อมูลแล้วหายก่อน flush ไม่มี snapshot บางส่วนหลุด
ผู้ตรวจพิสูจน์ด้วยว่าเริ่มโหลดใหม่แล้วโหลดไม่ครบ ACKของเซฟก่อนหน้าไม่ปลดโหลด/เปลี่ยนbaseline ผู้เขียนเพิ่มกรณีนี้เป็น regression ถาวรข้อที่15แล้ว ผ่าน
ไม่พบข้อบกพร่องคงเหลือจากกรณีที่ได้รับมอบหมาย ไม่มีการอ้างว่าตรวจ UI เบราว์เซอร์ มือถือ หรือระบบเซฟทุกสถานการณ์ที่อยู่นอกขอบเขตแล้ว
