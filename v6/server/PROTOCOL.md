# 📡 ข้อความ WebSocket ของ v6 (`/v6ws`)

โค้ดเซิร์ฟเวอร์: `v6/server/proto.cjs` · โค้ดเกม: `v6/src/core/net.js` · เวอร์ชันโปรโตคอล `PROTO_V = 1`
ทุกข้อความเป็น JSON 1 ก้อน มีช่อง `t` (ชนิด) · ช่อง `r` (เลขคำขอ ตัวเลข หรือข้อความ ≤32 ตัว) ไม่บังคับ — เซิร์ฟเวอร์ตอบ `r` เดิมกลับ ให้เกมจับคู่คำตอบกับคำขอได้

## เกม → เซิร์ฟเวอร์
| `t` | ต้องล็อกอินก่อน | ช่อง | เซิร์ฟเวอร์ตอบ |
|---|---|---|---|
| `time` | ไม่ | `c` = เวลาเครื่อง (ms) | `time` |
| `register` | ไม่ | `id` `pw` `name` | `auth_ok` (มี `token` `created:true`) · `auth_no` |
| `login` | ไม่ | `id` `pw` | `auth_ok` (มี `token`) · `auth_no` |
| `hello` | ไม่ | `id` `token` (เข้าต่อด้วยโทเคนที่จำไว้) · ต่อใหม่เองระหว่างเล่น: + `resume:1` `sid` (sid ของการโหลดล่าสุดของหน้านี้ · 1B-g N3) | `auth_ok` (ไม่มี token) · `auth_no why:'auth'` (โทเคนใช้ไม่ได้ → ลืมโทเคน) · `auth_no why:'rate'` (ถี่เกิน → **ไม่**ลืมโทเคน ต่อใหม่ช้าลง) · `auth_no why:'replaced'` (resume แต่เครื่องอื่นโหลดไปเล่นแล้ว → ไม่เตะเครื่องนั้น · เกมหยุดและถามผู้เล่น) |
| `load` | ใช่ | `sid` = สุ่ม 32 ตัวฐาน 16 ใหม่ทุกครั้งที่โหลด → เครื่องนี้เป็น**ผู้เขียนล่าสุด** (เครื่องอื่นเซฟไม่ได้แล้ว) | `load` · `err why:'rate'` (โหลดถี่กว่า 1 ครั้ง/5 วิ) |
| `save` | ใช่ | `seq` (เลขเพิ่มขึ้นทุกครั้ง ≥1) · `sid` (ของการโหลดครั้งล่าสุด) · `systems` `{ <id ระบบ>: ข้อมูลจาก save() }` | `save_ok` · `save_no` |
| `logout` | ใช่ | — (ลบโทเคนที่ใช้อยู่) | `bye` |

## เซิร์ฟเวอร์ → เกม
| `t` | ช่อง | ความหมาย |
|---|---|---|
| `welcome` | `v` (PROTO_V) · `s` เวลาเซิร์ฟเวอร์ ms | ส่งทันทีที่ต่อได้ |
| `time` | `c` (ค่าที่เกมส่งมา) · `s` เวลาเซิร์ฟเวอร์ | เกมคิด srvNow = `s + (ตอนนี้ − c)/2` |
| `auth_ok` | `id` `name` `gm` · `token` (เฉพาะ register/login) · `created` | ล็อกอินสำเร็จ — การเชื่อมต่อนี้ผูกกับบัญชีแล้ว |
| `auth_no` | `why` · `sec` (เฉพาะ locked) | ไม่สำเร็จ (ดูตาราง why) |
| `load` | `doc = { v, seq, upd, systems:{...}, server:{ coin } }` | เซฟของบัญชี (`seq:0` = ตัวละครใหม่) |
| `save_ok` | `seq` `upd` | บันทึกแล้ว |
| `save_no` | `why` · `seq` (เฉพาะ old = seq ล่าสุดบนเซิร์ฟเวอร์) | ไม่บันทึก |
| `bye` | — | ออกจากระบบแล้ว |
| `dupe` | — | ไอดีนี้ล็อกอินที่เครื่อง/แท็บอื่น → ตัวนี้ถูกตัดใน 0.3 วิ เซฟไม่ได้อีก |
| `err` | `why` (`bad` ข้อความผิดรูป · `auth` ยังไม่ล็อกอิน · `rate` ถี่เกิน · `busy` งบคำสั่งที่เก็บของ v6 เต็ม · `server` เซิร์ฟเวอร์พัง) | |

## รหัส `why`
| why | มาจาก | เกมแสดง |
|---|---|---|
| `bad-id` | register | ไอดีต้องเป็น a-z 0-9 _ หรือภาษาไทย 3–16 ตัว |
| `bad-pw` | register | รหัสผ่านต้องยาว 6–64 ตัว |
| `taken` | register | ไอดีนี้มีคนใช้แล้ว (ไอดี GM ก็ตอบแบบนี้) |
| `wrong` | login | ไอดีหรือรหัสผ่านไม่ถูกต้อง (ไม่บอกว่าไอดีมีหรือไม่) |
| `locked` + `sec` | login | ใส่รหัสผิดบ่อยเกิน รออีก `sec` วินาที (ผิด ≥8 ครั้ง ล็อก 20→40→…≤900 วิ) |
| `rate` | register/login/hello | ลองบ่อยเกิน (register+login >20 ครั้ง/นาที/IP · hello >10/นาที/IP หรือ >3/นาที/ซ็อกเก็ต) |
| `auth` | hello | โทเคนหมดอายุ (90 วัน) หรือถูกลบ → ล็อกอินใหม่ |
| `replaced` | hello (resume) | ไอดีนี้กำลังเล่นอยู่ที่เครื่องหรือแท็บอื่น — เครื่องนี้หยุดไว้ก่อน … กดปุ่ม "เล่นที่เครื่องนี้แทน" (รีโหลด = เปิดเกมใหม่ → เตะเครื่องนั้น) · ไม่ลืมโทเคน ไม่ต่อใหม่เองวน (ดู "เซสชันซ้อน") |
| `rate` | save | เซฟถี่กว่า 1 ครั้ง/วิ/บัญชี หรือ >2 ข้อความ/วิ/ซ็อกเก็ต (เกมรอแล้วส่งใหม่) |
| `replaced` + `seq` | save | `sid` ไม่ใช่ผู้เขียนล่าสุด = เครื่องอื่นโหลดไปเล่นต่อแล้ว → **เกมหยุดเซฟ ทิ้งของในเครื่อง แล้วโหลดใหม่** (ห้ามส่งทับ · ผลตรวจ 1B H3) |
| `old` + `seq` | save | `seq` ไม่มากกว่าของบนเซิร์ฟเวอร์ = เซิร์ฟเวอร์มีของใหม่กว่า → **เกมหยุดเซฟแล้วโหลดใหม่** เหมือน replaced (เดิม "+1 แล้วส่งใหม่" = ทับของเครื่องอื่น ยกเลิกแล้ว) |
| `busy` | ทุกคำสั่งที่แตะที่เก็บ | งบคำสั่งที่เก็บของ v6 เต็ม (กันโควตา Upstash เกมเดิม) → เซฟ: `save:status {ok:false, error:'busy'}` + ป้ายบนจอ "เซิร์ฟเวอร์ไม่ว่าง — ยังไม่ได้บันทึก กำลังลองใหม่เอง (อย่าเพิ่งปิดเกม)" · ถอยเวลา 5→10→20→40→60 วิ (เซฟอัตโนมัติ 30 วิไม่ลัดคิว) · โหลดครั้งแรกไม่สำเร็จก็ลองใหม่เองแบบเดียวกัน (1B-g N2) |
| `size` | save | systems ใหญ่เกิน 256 KB |
| `bad` | save | รูปแบบผิด (seq <1 · ไม่มี/ผิดรูป sid · ชื่อระบบผิด · >64 ระบบ) |

## กติกาฝั่งเซิร์ฟเวอร์ (ปรับตามผลตรวจ 1B · งาน 1B-f)
- `/v6ws` เปิดเฉพาะเมื่อ env `V6_ENABLE=1` · v6 โหลดไม่ได้/พัง → ปิด `/v6ws` เอง เกมเดิมบูตและทำงานต่อ
- **ต่อซ็อกเก็ต:** ≤30 ข้อความ/วิ และ ≤512 KB/วิ (เกิน → ตัด) · ผิดรูปครบ 10 → ตัด · ค้างในคิวเกิน 8 ข้อความ → ตัด (ที่เก็บช้าแล้วยิงรัว หน่วยความจำไม่บวม)
  · ยังไม่ล็อกอิน: ข้อความ ≤2 KB (ใหญ่กว่า → ตัด) และต้องล็อกอินภายใน 60 วิ (ไม่งั้นตัด รหัส 4002) · ล็อกอินแล้ว: ข้อความที่ไม่ใช่ `save` ≤4 KB · `save` ≤320 KB (systems ≤256 KB)
  · เก็บเข้าคิวแค่ช่องที่ใช้ (`t r id pw name token c seq sid systems`) ช่องอื่นทิ้ง
- **กันเผาโควตาที่เก็บ** (Upstash ใช้ร่วมกับเกมเดิม): hello ≤10/นาที/IP + ≤3/นาที/ซ็อกเก็ต · load ≤1/5 วิ/ซ็อกเก็ต + ≤20/นาที/IP · save ≤2/วิ/ซ็อกเก็ต + ≤1/วิ/บัญชี (นับทุกครั้งรวมที่ตอบ old)
  · **แคชเซฟ (1B-g N1):** ต่อบัญชีจำ "ข้อมูลเล็ก" `{seq, upd, w, server}` (≤20,000 บัญชี ~200 ไบต์/ตัว) + `systems` เป็น**สตริง** (ไม่ใช่อ็อบเจกต์)
    งบรวมของสตริงเป็นไบต์ `V6_SAVE_CACHE_MB` (ค่าเริ่ม 32 · นับ length×2) เกินงบ → ทิ้งสตริงของตัวที่ใช้นานสุด (ข้อมูลเล็กยังอยู่ → เซฟยังเป็น 1 คำสั่ง) · โหลดตัวที่ถูกทิ้ง = อ่านที่เก็บ 1 คำสั่ง
    เดิมเก็บเอกสารแบบอ็อบเจกต์ 500 ตัว → เซฟ `[[],[],…]` 256 KB บวมเป็น ~3.4 MB/ตัว · ยิง 100 บัญชี heap +333 MB (Render ฟรี 512 MB ล่มทั้งเกมเดิม) → ตอนนี้ +16 MB (เทส `server.heap.cjs` เกณฑ์ <30 MB)
  · **งบรวมทั้ง v6:** `V6_STORE_PER_MIN` (ค่าเริ่ม 120 คำสั่ง/นาที · นับในหน่วยความจำ) · `V6_STORE_PER_DAY` (ค่าเริ่ม 4000/วัน) เกิน → `busy`
    · งบวัน (1B-g N4): นับตามวันเวลาไทย (เริ่มใหม่เที่ยงคืนไทย) · ตัวนับเก็บในที่เก็บคีย์ `eld6:budget:day:<เลขวัน>` → **รีสตาร์ต/deploy ไม่รีเซ็ต** · อ่าน 1 ครั้งตอนเริ่ม · เขียนกลับทุก ~1% ของงบ (งบ 4000 → ทุก 40 คำสั่ง ห่าง ≥10 วิ) + ทุก 5 นาทีถ้ามีเปลี่ยน + ทันทีที่เต็ม (คำสั่งบันทึกตัวนับไม่หักงบ เพดาน ≈ งบ/100 + 288 ครั้ง/วัน)
      โปรเซสดับกะทันหันลืมได้ไม่เกิน ~40 คำสั่ง/5 นาทีล่าสุด · ใช้เกิน 80% → log เตือน 1 ครั้ง/วัน
    · **ตัวเลขให้เจ้าของตัดสินตอนตั้ง `V6_ENABLE=1`** (ไม่เปลี่ยนค่าเริ่มในงานนี้): เล่นปกติ 1 คน ≈ 120 คำสั่ง/ชม. (เซฟทุก 30 วิ) → 4000/วัน ≈ 33 ชั่วโมงผู้เล่นต่อวัน (เช่น 4 คน × 8 ชม.) · ช่วงเทสกลุ่มเล็กพอ ·
      เปิดจริงตั้งตามโควตา Upstash ที่เหลือของบัญชี (ดูหน้า Upstash) หักส่วนที่เกมเดิมใช้ · งบหมด = ทุกคนเซฟไม่เข้าจนเที่ยงคืนไทย (ผู้เล่นเห็นป้าย busy)
- ต่อพร้อมกันได้ ≤4 ต่อ IP (`MAX_PER_IP` · IPv6 นับทั้ง /64) · รวม ≤1000 (`V6_MAX_PLAYERS`) · ตารางในหน่วยความจำล้างของหมดอายุทุก 5 นาที + มีเพดาน
- **Origin:** ไม่มี Origin (ไม่ใช่เบราว์เซอร์) ผ่าน · โดเมนเดียวกับ host ผ่าน · อยู่ใน `ALLOWED_ORIGINS` ผ่าน · อื่น ๆ (รวม `null`) → 403
- **IP ผู้เล่น** (`V6_PROXY_HOPS`): ค่าเริ่ม `auto` = ถ้าคนที่ต่อเข้ามาตรงเป็นเครือข่ายภายใน/Cloudflare ไล่ `x-forwarded-for` จากขวา ข้ามพร็อกซี (ภายใน + ช่วง IP Cloudflare) ใช้ตัวแรกที่ไม่ใช่พร็อกซี ·
  ต่อตรงด้วย IP สาธารณะ → ไม่เชื่อ header · ตัวเลข N = ตัวที่ N นับจากขวา · 0 = ไม่อ่าน header · `V6_LOG_XFF=1` พิมพ์ header ดิบ 5 ครั้งแรก (ให้เจ้าของเช็กบน Render แล้วตั้งค่าตายตัว)
- **ผู้เขียนเซฟ:** โหลดด้วย `sid` ใหม่ → เซิร์ฟเวอร์จำ `w = sid` ในเอกสารเซฟ (ไม่ส่งกลับให้เกม) · เซฟที่ `sid` ไม่ตรง → `replaced` (แบบ writer/session-replaced ของเกมเดิม)
- ข้อความจากเครื่องเดียวกันทำทีละอันตามลำดับ (ส่ง login แล้ว load ต่อกันได้เลย)

## เซสชันซ้อน — ใครได้เล่น (1B-g N3 · ผลตรวจ 1B-f)
| เหตุการณ์ | ผล |
|---|---|
| พิมพ์รหัส (`login`/`register`) | เครื่องนี้ได้เล่น · เครื่องเก่าได้ `dupe` ถูกตัด (ตั้งใจย้ายเครื่อง) |
| เปิดเกม/รีโหลดหน้า แล้ว `hello` ด้วยโทเคน (ไม่มี `resume`) | เหมือนพิมพ์รหัส — เครื่องนี้ได้เล่น เครื่องเก่าได้ `dupe` |
| ซ็อกเก็ตหลุดแล้ว**ต่อใหม่เอง**ระหว่างเล่น (`hello` + `resume:1` + `sid`) และ `sid` = ผู้เขียนล่าสุด (`w`) | ต่อได้ตามปกติ (เน็ตกระตุก / เซิร์ฟเวอร์รีสตาร์ต) |
| ต่อใหม่เอง แต่ `w` ≠ `sid` (เครื่องอื่นโหลดไปเล่นแล้ว) | **ไม่เตะเครื่องที่เล่นอยู่** · เครื่องนี้ได้ `auth_no why:'replaced'` → หน้าบังจอไทย + ปุ่ม "เล่นที่เครื่องนี้แทน" (รีโหลด = แถวที่ 2) · ไม่ต่อใหม่เองวน · ไม่ลืมโทเคน |

**เหตุผล:** เกมเดิมทำแบบนี้อยู่แล้ว — `SERVER_BOOT.load` ตอน**เปิดหน้า**ส่ง `activate:true` + `document` ใหม่ (spec05 §2.5) ทำให้แท็บนั้นเป็นผู้เขียน ส่วน ws ที่ต่อใหม่เองส่ง `document` เดิมของแท็บ → `ACC.verify(id, token, document)` (`accounts.js:388`) ไม่ผ่านถ้ามีแท็บอื่น activate ไปแล้ว → แท็บเก่าต่อไม่ได้ (เตะใครไม่ได้) แต่แท็บที่**เปิดใหม่**เตะแท็บเก่าได้ (`dupe` · `world.js:70`)
v6 ใช้ `sid` (สุ่มต่อการโหลด) แทน `document`: การต่อใหม่เองไม่ใช่การตัดสินใจของผู้เล่น (มือถือพักแท็บแล้วตื่นมาเอง) จึงห้ามเตะคนที่กำลังเล่น · การเปิดเกม/พิมพ์รหัส คือผู้เล่นตั้งใจ จึงให้ชนะเหมือนเกมเดิม
· เซิร์ฟเวอร์ตรวจ `w` และผูกเซสชันในคิวเดียวกันของบัญชี (`saves.claim`) → `load` ของเครื่องอื่นแทรกกลางไม่ได้ · ใช้ข้อมูลเล็กในแคช (ปกติไม่แตะที่เก็บ)
· ของที่เล่นบนเครื่องที่ได้ `replaced` หลังเซฟล่าสุด (≤30 วิ) ไม่ถูกบันทึก — เหมือนเกมเดิม (`session-replaced` → kick) และไม่มีของซ้ำ/เสกเงิน (H3)
· เทส: `save.test.js` "N3: A พักแท็บ…" (A ใช้ core/net จริงต่อ proto จริง · B เล่น+เซฟ · A ตื่น → B ไม่โดน dupe เซฟต่อได้ · A ได้ replaced · กดเล่นที่ A → B ได้ dupe)

## ข้อจำกัดที่รู้แล้ว — หลายโปรเซส (1B-g N5 · ผลตรวจ 1B-f)
- แคชเซฟ (`seq`/`w`/systems) และตัวนับต่อนาที/ต่อ IP อยู่ในหน่วยความจำของโปรเซส → **ถือว่า Render รัน v6 โปรเซสเดียว** (เป็นอย่างนั้นตอนนี้: เกมเดิม + v6 อยู่ใน `server.js` ตัวเดียว · แผนฟรี 1 instance)
- ช่วง deploy โปรเซสเก่ากับใหม่อาจทำงานซ้อนกันชั่วครู่: เครื่อง A อยู่โปรเซสเก่า (แคช `w=sA`) · เครื่อง B โหลดบนโปรเซสใหม่ (เขียน `w=sB` ลงที่เก็บ) → A เซฟผ่านเพราะดูแคชตัวเอง → ทับของ B ได้ในช่วงนั้น · ตัวนับงบวันต่างคนต่างเขียน (นับขาดได้ช่วงสั้น ๆ)
  โอกาสต่ำมาก (ต้องสลับเครื่องตรงช่วง deploy ไม่กี่วินาที) และ Render ตัดซ็อกเก็ตของโปรเซสเก่าเมื่อปิด → A ต่อใหม่เข้าโปรเซสใหม่ → `resume` ได้ `replaced` (N3)
- **ทางแก้ถ้าวันหนึ่งต้องรันหลายตัว / scale:** (1) เขียนเซฟแบบมีเงื่อนไขในที่เก็บเอง — Upstash สคริปต์ Lua / `WATCH` ตรวจ `w`+`seq` แล้วค่อย `SET` ในคำสั่งเดียว (แบบ CAS ของเกมเดิม spec05 §2.4) → แคชเหลือแค่ลดการอ่าน ไม่ใช่ตัวตัดสิน
  (2) หรือถือแคชไม่เกิน ~60 วิ แล้วอ่าน `w`/`seq` จากที่เก็บใหม่ (เพิ่ม 1 คำสั่ง/เซฟหลังว่าง) (3) ตัวนับงบวันใช้ `INCRBY` ของ Upstash (อะตอมมิก) แทน get/set · (4) ตัวนับต่อ IP ย้ายไปที่เก็บร่วม
  ยังไม่ทำตอนนี้ เพราะเพิ่มคำสั่ง Upstash (โควตาใช้ร่วมเกมเดิม) และ Render ตอนนี้โปรเซสเดียว
- **เครื่องผู้เล่นเขียน `server.*` (เงิน) ไม่ได้** — `save` รับแค่ `seq` + `sid` + `systems` ส่วน `server` ใช้ของบนเซิร์ฟเวอร์เสมอ (DECISIONS 2026-10-30)
- เก็บที่ Upstash (มี env ครบคู่) หรือไฟล์ `DATA_DIR/v6/` (สร้างโฟลเดอร์ตอนเขียนครั้งแรก) · คีย์ขึ้นต้น `eld6:` ไม่ปนเกมเดิม
