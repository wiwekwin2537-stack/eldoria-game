# เฟส 0 — แกะสเปกระบบเดิม (คำสั่งจากหัวหน้างาน)

เป้าหมายโปรเจกต์ v6: เขียนเกมตำนานเอลโดเรียใหม่ทั้งหมดให้โค้ดสะอาด **ระบบ/ตัวเลข/หน้าตาเหมือนเดิม** แต่ไม่มีการห่อทับฟังก์ชัน (monkey-patch) อีก
งานของคุณในเฟสนี้: **อ่านโค้ดเดิม แล้วเขียนสเปกว่าระบบ "สุดท้ายจริง" ทำงานอย่างไร** ให้ทีมที่เขียนใหม่ใช้ได้โดยไม่ต้องเปิดโค้ดเดิมอีก

## ห้าม
- ห้ามแก้/ลบไฟล์ใดๆ ในโปรเจกต์ ยกเว้นไฟล์สเปกของคุณใน `v6/spec/` และแถวงานของคุณใน `v6/TASKS.md`
- ห้ามรันเซิร์ฟเวอร์จริง (รันในเครื่องเพื่อตรวจได้ถ้าจำเป็น · ใช้พอร์ตของตัวเอง ไม่ใช่ 8787)

## กันงานหายเมื่อโควตาหมด (บังคับ · เพิ่ม 2026-10-30)
- **เขียนไฟล์สเปกตั้งแต่ต้น แล้วเติมทีละหัวข้อ** อย่าเก็บไว้เขียนทีเดียวตอนท้าย
- บรรทัดแรกของไฟล์: `สถานะ: กำลังทำ — เสร็จหัวข้อ ... · ต่อไป ...` (อัปเดตทุกครั้งที่ push) · เสร็จแล้วเปลี่ยนเป็น `สถานะ: รอตรวจ`
- **commit + push เฉพาะไฟล์สเปกของตัวเอง ทุก 30–45 นาที และก่อนหยุด**: `git add v6/spec/<ไฟล์> && git commit -m "v6 spec <ชื่อ>: ..." && git pull --rebase origin main && git push origin HEAD:main` · ห้าม add ไฟล์อื่น
- AI ตัวใหม่มารับต่อ: อ่านบรรทัดสถานะ แล้วทำต่อจากหัวข้อถัดไป ไม่เริ่มใหม่

## วิธีอ่านโค้ด
- โค้ดเกมอยู่ `js/` โหลดตามลำดับ `<script src>` ใน `index.html` · ฟังก์ชันเดียวกันถูกห่อทับหลายชั้น (`const _x=fn;fn=function(){...}`) → **พฤติกรรมสุดท้าย = ทุกชั้นรวมกันตามลำดับโหลด** ชั้นหลังชนะ
- ใช้ `SYSTEMS.md` หาหมวดของคุณ (ตารางฟังก์ชัน + ชั้นที่ห่อ + ชุดแก้) แล้วเปิดเฉพาะบรรทัดที่เกี่ยว ใช้ grep ไม่ต้องอ่านไฟล์ทั้งไฟล์ (`js/031-core.js` ใหญ่ ~1MB)
- `js/005-core.js` มีภาพ base64 ขนาดใหญ่ — อย่าพิมพ์ออกมา
- คำสั่งเจ้าของ: grep `GAME_DESIGN.md` และ `TASKS.md` (คำว่า "เจ้าของสั่ง") สำหรับหมวดของคุณ — คำสั่งเจ้าของชนะโค้ด ถ้าขัดกันให้จดไว้
- โค้ดที่ปิดใช้แล้ว (ไม่โหลด / ถูกชั้นหลังลบทิ้ง / เจ้าของสั่งเอาออก เช่น ระบบฟาร์มเกษตร ภาพตัวละครจาก ChatGPT) → จดว่า "ตัดออก" ไม่ต้องบรรยาย

## ไฟล์ที่ต้องส่ง: `v6/spec/<ชื่อหมวด>.md` (ภาษาไทย · ชื่อตัวแปร/ฟังก์ชันเป็นอังกฤษ · กระชับ ไม่เกิน ~30KB ต่อไฟล์)
แต่ละระบบในหมวด เขียนหัวข้อนี้:
1. **ผู้เล่นเห็น/ทำอะไร** — ขั้นตอนจริงที่ผู้เล่นใช้ (เข้าตรงไหน กดอะไร ได้อะไร)
2. **กติกาและตัวเลข** — สูตร ค่าคงที่ อัตราดรอป คูลดาวน์ ราคา เป็นตัวเลขจริงตามชั้นสุดท้าย + ที่มา `ไฟล์:บรรทัด`
3. **ตารางข้อมูล** — ชื่อตัวแปรที่เก็บตาราง (เช่น `CLS`, `PNODES`, `ITEMS`) + ไฟล์:บรรทัดที่ประกาศ/ถูกแก้ทุกจุด (ทีมเฟส 1 จะดึงออกเป็นไฟล์ข้อมูล)
4. **หน้าจอ/ปุ่ม** — UI ที่เกี่ยว (คอม/มือถือ/จอยเกม)
5. **ออนไลน์** — ข้อความที่คุยกับเซิร์ฟเวอร์ (ชื่อ type ของ ws / API) และอะไรที่เซิร์ฟเวอร์ตัดสิน
6. **เชื่อมกับระบบอื่น** — เรียกใช้/ถูกเรียกจากระบบไหน
7. **บัค/ความขัดกันที่เจอ** — สิ่งที่ชั้นต่างๆ ทำขัดกัน หรือขัดคำสั่งเจ้าของ (ข้อเสนอว่าเวอร์ชันใหม่ควรเลือกแบบไหน)

ปิดท้ายไฟล์ด้วย "ส่วนที่ยังไม่แน่ใจ" (ซื่อตรง ถ้าแกะไม่ออกให้บอก)
