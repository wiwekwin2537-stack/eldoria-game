# คำสั่งผู้ตรวจอิสระ เฟส 0 (จากหัวหน้างาน)

คุณ **ไม่ใช่** คนเขียนสเปกที่ได้รับ · งาน: ตรวจว่าสเปก "ตรงกับเกมเดิมจริง" พอให้ทีมเขียนเกมใหม่โดยไม่ต้องเปิดโค้ดเดิม
อ่านก่อน: `v6/PLAN.md` · `v6/DECISIONS.md` · `v6/spec/_BRIEF.md` (รูปแบบสเปก + กติกากันงานหาย)

## วิธีตรวจ
1. สุ่มตรวจ **ตัวเลข/สูตร/ไฟล์:บรรทัด อย่างน้อย 25 จุดต่อสเปก** เทียบกับโค้ดจริงใน `js/` (เลือกจุดที่ส่งผลต่อการเล่นมากก่อน: สูตร ราคา คูลดาวน์ อัตรา) · ตรวจว่ามองครบทุกชั้นที่ห่อทับ (ค้น `ชื่อ=function`)
2. หา **ระบบที่หายไป** — เทียบหัวข้อใน `SYSTEMS.md` หมวดที่เกี่ยว + รายชื่อ fix ทั้งหมด ว่ามีระบบไหนในเกมที่สเปกไม่พูดถึง
3. ถ้าจำเป็นเปิดเกมในเครื่องเพื่อยืนยัน: `DATA_DIR=<โฟลเดอร์ชั่วคราวของคุณ> PORT=<88xx ห้าม 8787/8799> node server.js` ปิดเมื่อเสร็จ (ปิดเฉพาะ pid ของตัวเอง)
4. **แก้ในไฟล์สเปกได้เลย** เมื่อมั่นใจว่าผิด (ใส่ ✏️ ท้ายบรรทัดที่แก้) · ไม่มั่นใจ → เขียนในหัวข้อใหม่ท้ายไฟล์ `## ผลตรวจอิสระ`
5. ขัดกับ `v6/DECISIONS.md` → ไม่ต้องแก้ระบบเดิมในสเปก แต่เติมบรรทัด "v6: ใช้ตาม DECISIONS" ใต้ระบบนั้น

## ส่งงาน
- ท้ายไฟล์สเปก `## ผลตรวจอิสระ (วันที่ · ผู้ตรวจ)`: จำนวนจุดที่ตรวจ · ผิดกี่จุด (แก้แล้ว/ยังไม่แน่ใจ) · ระบบที่หายไป · คะแนนความเชื่อถือ ผ่าน / ผ่านแบบมีข้อแก้ / ไม่ผ่าน
- บรรทัดแรกสถานะ: `สถานะ: ผ่านตรวจ` หรือ `สถานะ: ตรวจแล้ว ต้องแก้ — ...`
- push ตามกติกาใน _BRIEF (เฉพาะไฟล์สเปกที่ได้รับ · ทุก 30–45 นาที และก่อนหยุด)
- ตอบหัวหน้า: ผลแต่ละไฟล์ + ปัญหาหนักสุด 3 ข้อ (สั้น)
